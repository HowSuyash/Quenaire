## 1. Purpose and scope

This policy sets out how Suyash Shukla, sole proprietor, protects the information held — both its own and that of clients.

It applies to everyone who works on client projects, including contractors, and to every
device and service used to do that work.

The organisation is a single practitioner. Where this policy refers to staff or contractors, it applies to any person engaged for a specific piece of work.

## 2. Responsibility

Suyash Shukla, Founder & Principal Developer, is accountable for information security. This includes
approving this policy, deciding on exceptions, and acting as the contact point for client
security queries and for incidents.

There is no separate security team. Where this policy assigns a task, it is performed by the
named owner above unless stated otherwise.

## 3. Access control

- Multi-factor authentication is enabled on every account used for client work: email,
  hosting, source control, domain registrar, CRM, and payment providers.
- Credentials are stored in Bitwarden. They are not kept in browsers, notes applications, spreadsheets, or chat messages.
- Multi-factor recovery codes are stored in Bitwarden, not on the device used to log in.
- Passwords are unique per service and generated by the password manager.
- Access to a client's systems is requested only where needed for the work, and removed when
  the engagement ends.
- Shared accounts are avoided. Where a client's own system permits only one login, the credential is held in Bitwarden and used only by the practitioner named in section 2.

## 4. Devices

- Work is performed on a single personal laptop running Windows 11 Pro. Because the device is not company-owned, the controls in this section apply to it in full, and client data is kept only in the services listed in section 6 rather than in personal storage.
- Full-disk encryption is enabled on every device used for client work.
- Devices lock automatically after 5 minutes of inactivity and require a password to wake.
- Operating system and browser updates are applied within 14 days of release.
- Microsoft Defender Antivirus runs on all Windows devices with real-time protection enabled and signatures updated automatically.
- Devices are not left unattended in public spaces, and screens are not visible to others when
  working outside a private space.

## 5. Networks

- Client systems are accessed over a trusted network or a VPN. Public or untrusted Wi-Fi is not
  used for administrative access without a VPN.
- No VPN is currently in use. Work is performed only on the practitioner's own home network, which uses WPA2 or better. Client systems are not accessed from public Wi-Fi.

## 6. Client data

- Client data is used only to deliver the agreed work.
- Production data is not copied into development or test environments. Where realistic test
  data is needed, it is fabricated or anonymised.
- Client data is not stored on removable media.
- Client data is retained for the duration of the engagement plus 30 days, after which it is deleted from all systems including backups and local devices.
- On request or at contract termination, client data is deleted and written confirmation is
  provided.

## 7. Development security

The following are in place today:

- All source code is held in version control, giving a full change history and the ability to
  roll back a release.
- Application secrets are supplied through environment variables. No credential is committed to
  the repository; only example files with placeholder values are stored.
- Dependencies are scanned automatically for known vulnerabilities as part of the build.
- Static analysis runs against the codebase as part of the build.

The following are commitments:

- Changes are reviewed before release. As a single practitioner there is no second reviewer, so review takes the form of a self-review against a written checklist, recorded in the version control history, plus the automated dependency and static analysis checks described above.
- Known vulnerable dependencies are remediated within 14 days for critical and high severity, and 60 days for medium.
- Development, staging and production environments are kept separate, with separate credentials.

## 9. Incidents

An incident is any suspected loss, exposure, or unauthorised access to client data or systems,
including a lost device or a compromised account.

On becoming aware of one:

1. Contain it — revoke credentials, isolate the affected system.
2. Record what happened, when it was noticed, and what data may be involved.
3. Notify affected clients within 48 hours of confirming the incident.
4. Where legally required, notify the relevant authority within the mandated timeframe.

## 10. Continuity

- Source code, documentation and configuration are held in Git version control, hosted in a **private** GitHub repository. Client project work is kept in a repository separate from internal product code, and the client is granted access to their own.
- Application databases and uploaded files are backed up daily by the hosting provider's managed backup service, retained for 7 days, and stored in the same region as the primary data. Source code is additionally held in the remote Git repository.
- A restore is tested at least annually. Last tested: not yet tested — a restore test will be performed before the application is handed over to the client.
- **Key person risk.** The organisation is a single practitioner, so unavailability is the
  most significant continuity risk. It is limited by:
  - clients holding their own hosting, domain and CRM accounts, with access granted to
    the practitioner rather than owned by them;
  - all source code, configuration and documentation held in the client-accessible
    repository, so another developer can continue the work;
  - no emergency contact is currently nominated for credential recovery. This is a known gap for a single practitioner; clients holding their own accounts is the compensating control.

## 11. Acceptable use

- Work accounts and devices are used for work.
- Client information is not shared outside the organisation without the client's agreement.
- Software is installed only from trusted sources.
- Suspected phishing is reported to the owner named above and not acted on.

## 12. Exceptions and review

Any departure from this policy is agreed in advance with the owner named above and recorded,
with the reason and a date for review.

This policy is reviewed at least annually, and after any significant incident or change to how
the business operates.
